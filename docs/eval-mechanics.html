How the evals work.

Two suites, because the two things under test produce different kinds of answers. The judge outputs a verdict — one right answer per case, so its suite is a human-labelled golden set. The authors output a document — many valid answers per input, so their suite is a property contract: rules any valid output must satisfy, with no golden text at all. That distinction organizes everything on this page.

Suite 1 · the judge

A labelled golden set

The golden set is 14 hand-written fake artifact snippets, each constructed to pass or fail exactly one check, with the correct verdict decided by a human before any model ran. The runner (run_evals.py) feeds each snippet — together with the production rubric, critic-rubric.md, verbatim — to the real judge via claude -p, parses the one-line VERDICT: PASS / VERDICT: REVISE, and scores agreement with the pre-written label.

Why the cases are organized by check, not by stage.

The judge's unit of judgment is the dimension — a stage is just a bundle of dimensions. If a case were a whole stage artifact and the judge got it wrong, you wouldn't know which check broke. So each case isolates one check: a snippet with exactly one planted defect (or its clean mirror image), and a miss diagnoses itself.

6 structural checks × (1 planted PASS + 1 planted FAIL) + 2 adversarial = 14

Dimensions 4 (strategic fit) and 6 (falsifiability) have no PASS/FAIL pair — they are substantive: the judge may only emit a question with an owner, never a verdict, so there is no verdict to label. Dimension 4 appears only inside FW-01, where the absence of a verdict is what's being tested.

Suite 2 · the authors

A property contract

No golden.json here, by design: a fixed full-text answer would false-fail every valid rewrite. Instead the runner (run_author_evals.py) feeds each stage's verbatim author prompt (parsed from stage-prompts.md at run time) the frozen artifacts of examples/surprise-charge/, generates a fresh document via claude -p, and scores it against regex properties that must hold for any valid output. Two modes: --check-committed scores the committed example run itself — 26/26, which validates the properties before they're trusted on fresh output — and the default fresh-generation run is the regression gate for author-prompt edits.

Structure, never quality.

Not one property judges whether the writing is good. They check presence, provenance, and vocabulary — the objective skeleton of each artifact. That's deliberate, and it draws the honest boundary: this suite catches a prompt that stops producing its contract (untagged figures, blockers without owners, a missing scope boundary). It does not catch writing that got worse while still ticking every box — quality belongs to the judge at runtime and to Layer 3, the designed-but-not-yet-run outcome evals with human labels.

Stage 0 (intake) is interactive — it needs a scripted human — and is out of scope here; its behavior is exercised by the judge suite and the challenge-budget rules in SKILL.md.

A subjective rule made mechanical — the worked example. "Never invent a figure" sounds like a judgment call. The S1 TAGS property is that rule as code: find every % figure, and demand a provenance tag or a sanctioned gap near it. This is the check, verbatim from run_author_evals.py: 
def pct_lines_tagged(t):
    """Every % figure must have a provenance tag or a sanctioned gap nearby
    (within 160 chars after it — markdown hard-wraps lines, so a line-based
    check false-fails). This is the never-invent-a-figure contract."""
    for m in re.finditer(r"\d+(\.\d+)?\s?%", t):
        window = t[m.start():m.end() + 160]
        if not re.search(r"\[(OBSERVED|REPORTED|ASSUMED|UNKNOWN|NEEDS EVIDENCE)", window):
            return False
    return True
The docstring records its own bug-fix: the first version checked line-by-line and false-failed the committed press release, because markdown hard-wraps put "71%" and its [OBSERVED] tag on different lines. The property was wrong, not the artifact — which is exactly why the committed-run sanity mode exists.
