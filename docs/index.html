Working Backwards that doesn't stop at the press release.

+This runs all nine stages — press release, FAQs, demo, docs, telemetry, requirements, release plan, readiness — with an LLM judge gating each one. Every requirement cites the paragraph it came from, because a requirement that can't cite anything is a fairly precise definition of scope creep.

Prompt → artifact → judge → you. Repeat nine times.

1You prompt the stage

One stage at a time. Every prompt ends with do not continue.

2The agent writes the artifact

The artifact, written to disk — every claim tagged, no invented figures.

3LLM as judge

Six checks get verdicts — PASS / REVISE / BLOCK. Strategy and feasibility only ever get questions routed to a named human.

4You gate

Accept, send back, or override — logged, never argued. Then the next stage unlocks.

The Surprise Charge: you forget the free trial ends, you get billed, you're furious.

A fictional subscription app, a problem everyone has had. The PM arrives saying "we need reminder emails" — and the first thing the skill does is push back. Arrow keys work.

What it produced

All nine stage prompts ship in the skill: stage-prompts.md

The complete artifact — and the model's pushback

Five blockers, before a single requirement existed.

Surfaced by the hostile-question banks at Stage 2 — each a question with an owner, never a finding. The skill has no way to mark its own question resolved.

The interesting one: BLK-01 turned the finance-vs-product disagreement into an experiment both sides are bound by.

One honest word, carried all the way down.

Finance thinks reminders cost conversions; product disagrees; neither has data. So the claim is tagged [ASSUMED] at intake — and the tag survives into the press release, the experiment requirement, and the readiness failure modes. A belief never gets rounded up to a fact.

PMs read this as a to-do list, which is exactly what it is. A tool that tells you what it doesn't know is more trustworthy than one that doesn't.

The problem paragraph, tags inline

38% of refunds cite "forgot to cancel" [OBSERVED: refund log], and 71% of eventual refunders never opened the app after day 3 [OBSERVED: activity × billing]. Their reviews say "tricked" [REPORTED: verbatims]. We believe reminders won't reduce conversion [ASSUMED — C5, finance disagrees; the experiment settles it]. [UNKNOWN: how many are surprised but silent — never refund, never write in]
