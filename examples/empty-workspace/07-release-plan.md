# Release plan — Empty Workspace

Four vertical slices. Instrumentation ships first and dark; the blocked slice is the one
carrying the privacy surface — and the plan says so instead of estimating around it.

## Slices

```
R1 · Measure before you move
Requirements: REQ-D1, REQ-D2
Depends on: —
Blocked by: —
Ships: the invite funnel instrumented end to end, including abandoned attempts; D14MR computable per cohort. Dark — no user-facing change.
Independently testable: yes
Test harness:
  - Composer open-and-close produces attempted with no sent
  - Full sequence produces four ordered events
  - D14MR excludes members with zero actions on a seeded cohort
Why first: C7 says nobody knows how many people already try to invite and fail. Moving a funnel you haven't measured is how the last two onboarding changes shipped twice and taught nothing (IFAQ-01).
```

```
R2 · The workspace does work on arrival
Requirements: REQ-DP2
Depends on: —
Blocked by: BLK-03
Ships: template gallery replaces the blank empty state; Start empty preserved; load-failure fallback.
Independently testable: yes
Test harness:
  - Gallery renders on first open; Start empty is the last card
  - Template creates content without replacing existing content
  - Simulated load failure falls back to blank canvas with retry
Not schedulable: BLK-03 — growth and product both claim this surface; the last collision shipped conflicting experiments. One named owner unblocks both R2 and R3.
```

```
R3 · The invite step, typed addresses only
Requirements: REQ-DP1, REQ-DP4, REQ-DP5
Depends on: R1
Blocked by: BLK-03
Ships: invite step in first-run (skippable, never-nag), composer everywhere, per-invite status including bounced.
Independently testable: yes
Test harness:
  - Skip is one click, no dialog, same destination as send
  - Bounce renders in composer with resend; server failure preserves chips
  - 30-day never-nag assertion: no scheduled re-prompt event exists
```

```
R4 · Import and the experiment
Requirements: REQ-DP3, REQ-D3
Depends on: R1, R3
Blocked by: BLK-01, BLK-02, BLK-04, BLK-06
Ships: contact import (if review permits) and the holdback readout on the causal claim.
Independently testable: yes
Test harness:
  - Import retains only selected addresses; non-selected discarded at session end
  - Holdback assignment at creation; readout states effect size, CI, cohort sizes, or declares underpower
Rests on assumption: REQ-D3 rests on C5 — the slice exists to test the assumption the initiative rests on.
Not schedulable: four blockers, three of them determining whether import ships at all.
```

## Dependency DAG

```
R1 ──▶ R3 ──▶ R4  [BLOCKED BY BLK-01 · 02 · 04 · 06]
 
R2 (parallel)      [BLOCKED BY BLK-03, with R3]
```

Edge list:
```
R1 -> R3
R3 -> R4
R1 -> R4
```

Checks: acyclic · all 8 requirements in exactly one slice · no orphans · no duplicates.

## Not schedulable

| Slice | Blocked by | Owner role | What unblocks |
|---|---|---|---|
| R2, R3 | BLK-03 | VP Product | One named owner for the onboarding surface |
| R4 | BLK-01 | privacy counsel | Lawful basis + non-user retention for imported contacts |
| R4 | BLK-02 | compliance lead | Invite email classification per market |
| R4 | BLK-04 | data & analytics lead | Experiment power at current volume |
| R4 | BLK-06 | security lead | OAuth scope + token storage review |

R1 is schedulable today and is the only slice that requires no meeting. That is the honest
plan: measure now, and unblock the rest with three conversations.
